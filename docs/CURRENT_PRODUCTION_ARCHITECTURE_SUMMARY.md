# 운영 웹앱 작업 및 역할 요약

기준일: 2026-08-12

## 1. 현재 구성

운영 웹앱은 GitHub Pages의 정적 화면, Google Apps Script(GAS), Firebase를 함께 사용한다.

| 구분 | 현재 역할 |
|---|---|
| 정적 웹앱 | 화면 표시, 양식 선택·입력·정렬, 알림 설정·내역, 사용자 입력 검증 |
| GAS | 엑셀 양식 업로드·변환, XLSX 파일 생성, 기존 시트 데이터와 검증 데이터 제공 |
| Firebase | 양식 조회 캐시, 측정값 저장 처리, 알림 기기·키워드 관리, 게시글 확인과 FCM 발송 |
| Google Sheets | 운영 양식 원본, 측정값 최종 저장소, FormList 및 기존 레거시 알림 자료 보관 |

## 2. 기능별 처리 위치

### 양식 목록 및 측정값 입력폼 조회

- **GAS**: Google Sheets의 `FormList`와 각 양식 데이터를 읽어 Firebase 게시용 원본을 제공한다.
- **Firebase Functions**: 5분마다 변경된 양식을 확인해 Firestore의 `publicCache/formList`, `publicForms`에 게시한다.
- **웹앱**: 운영 화면에서는 GAS로 직접 조회하지 않고 Firestore 공개 캐시에서 목록과 입력폼을 읽는다. 조회 실패 시 GAS로 우회하지 않고 오류를 표시한다.

### 엑셀 양식 업로드

- **GAS**: 업로드된 엑셀을 Google Sheets 양식으로 변환하고 `FormList`에 등록한다.
- **Firebase**: 정기 게시 작업이 새 양식 또는 변경된 양식을 Firestore 캐시에 반영한다.

### 측정값 저장

- **웹앱**: 입력값과 양식 버전을 Firebase의 `submitMeasurements`로 전송하고 처리 상태를 조회한다.
- **Firebase / Firestore**: 중복 저장 방지 키, 양식 버전, 행 식별값, 저장 게이트를 검증하고 저장 요청 상태를 관리한다.
- **Firebase Functions → Google Sheets API**: 승인된 값을 해당 운영 시트 F열에 기록하고 `FormList` 최근 수정일을 갱신한다.
- **GAS**: 현재 측정값 저장 경로에는 참여하지 않는다.
- 최근 수정일은 서울 시간의 실제 날짜값으로 저장하며 표시 형식은 `yyyy-mm-dd h:mm:ss`이다.

### XLSX 다운로드

- **GAS**: 선택한 Google Sheets 양식을 임시 스프레드시트로 복사해 XLSX Base64 파일을 생성한다.
- **웹앱**: 양식을 불러온 직후 GAS에 XLSX 생성을 요청하며, 저장하지 않아도 최근 수정일을 포함한 파일명으로 다운로드 버튼을 활성화한다.
- 입력값을 수정하면 저장되지 않은 값이 파일에 포함되는 오해를 막기 위해 기존 준비 파일을 무효화하고, 저장 완료 후 새 파일을 다시 준비한다.

### 알림 설정·발송·내역

- **Firebase Functions / Firestore**: `deviceId`·`deviceSecret`, FCM 토큰, 키워드, 활성 상태, 토큰 소유권과 수신 확인을 관리한다.
- **Firebase Functions**: 10분마다 해피휴게더 게시판을 직접 확인하고 새 게시글이 키워드와 일치하면 FCM을 발송한다. GAS 게시글 브리지는 사용하지 않는다.
- **웹앱·서비스워커**: 알림 권한과 기기 등록을 처리하고, 수신한 알림 내역을 해당 브라우저의 IndexedDB에 최대 100건 보관한다.
- **GAS / Google Sheets**: 과거 `FCM_Tokens` 자료는 최초 Firebase 이관 원본으로만 사용한다. 현재 알림 등록·수정·발송의 주 경로는 Firebase이다.
- 기존 GAS의 레거시 알림 API 코드는 호환 자료로 남아 있으나 새 알림 설정 화면에서는 사용하지 않는다.

### 입력값 검증·화면 편의 기능

- **GAS**: 기존 DB/시트 기반 입력 검증값을 제공한다.
- **웹앱**: 값 검증, 즐겨찾기, 항목 정렬, 입력 간격, 지도 화면과 메뉴 상태를 처리한다.
- 정렬 버튼의 CSP 문제, 햄버거 메뉴 크기, 알림 화면 왕복 시 과거 UI가 복원되는 탐색 캐시 문제를 수정했다.

## 3. 최근 적용 내역

- 테스트웹앱에서 검증한 Firestore 양식 조회, 비동기 측정값 저장, Firebase 알림 구조를 운영앱에 적용했다.
- 측정값 저장 게이트와 알림 발송 게이트를 운영 승인에 따라 활성화했다.
- 알림 내역·설정 문서와 관련 자산을 미리 불러오도록 하여 이동 체감 속도를 개선했다.
- 메인 문서와 알림 문서에 버전을 지정해 뒤로가기 시 오래된 메인 UI가 복원되지 않도록 했다.
- 저장 전 XLSX 다운로드와 최근 수정일 기반 파일명을 지원한다.
- FormList 최근 수정일을 율리24와 동일한 날짜값·표시 형식으로 통일했다.

## 4. 검증 및 운영 주의사항

- 운영 검증 양식은 승인된 **구명154**만 사용한다.
- **호포24, 호포154, 율리24는 운영 검증용으로 사용하지 않는다.**
- 웹앱 자동 테스트 54개와 Firebase Functions 테스트 52개가 통과했다.
- 구명154에서 저장하지 않고 XLSX 버튼이 최근 수정일 파일명으로 활성화되는 것을 확인했다.
- 기존에 ISO 문자열로 저장된 FormList 최근 수정일은 해당 양식이 다음번에 정상 저장될 때 새 날짜 형식으로 교체된다.
