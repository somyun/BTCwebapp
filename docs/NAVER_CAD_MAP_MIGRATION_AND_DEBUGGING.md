## 1. 문서 목적

이 문서는 호포기지 도면보기 기능을 카카오맵에서 네이버 지도 JavaScript API v3로 전환한 이유와 구현 구조, 모바일 지도 확대·축소 문제의 진단 과정, 최종 해결 내용 및 검증 방법을 기록한다.

현재 운영 기준은 모바일, 특히 삼성 인터넷 브라우저에서의 사용성이다. PC Edge에서 확대·축소 애니메이션 중 네이티브 마커와 SVG가 잠시 사라지는 현상은 브라우저 렌더링 계층의 차이로 확인했으며, 실제 주 사용 환경인 모바일 삼성 인터넷에서는 같은 현상이 발생하지 않아 PC 전용 우회 코드는 추가하지 않았다.

## 2. 전환 배경과 기술 선택

기존 카카오맵 웹 SDK에서는 도면 업무에 필요한 세부 확대 수준을 확보하기 어려워 별도의 `추가확대` 기능과 UI가 필요했다. 이 기능은 지도 SDK의 기본 확대와 별도로 도면을 강제 확대해야 했기 때문에 좌표 동기화, 검색 위치, 화면 회전 및 조작 코드의 복잡도를 높였다.

네이버 지도 JavaScript API v3는 웹 지도에서 zoom 21까지 기본 확대를 지원하므로 다음 방향으로 전환했다.

- `추가확대` 버튼과 별도 확대 배율 제거
- 네이버 지도의 기본 확대·축소 및 핀치 제스처 사용
- CAD 도면을 네이버 지도 오버레이 계층 안의 SVG로 렌더링
- 지도 SDK의 기본 이동·확대 애니메이션을 그대로 활용
- PC보다 실제 주 사용 환경인 모바일 브라우저 동작을 우선 검증

## 3. 인증 및 보안 구성

프런트엔드에서는 네이버 클라우드 Maps의 Dynamic Map용 `ncpKeyId`만 사용한다. 값은 `index.html`의 `naver-maps-ncp-key-id` 메타 태그에서 읽는다.

네이버 클라우드 콘솔에는 실제 사용하는 Web 서비스 URL을 정확한 Origin 단위로 등록해야 한다.

- 운영: `https://somyun.github.io`
- 로컬: `http://localhost:8080`

`localhost`와 `127.0.0.1`은 서로 다른 Origin이다. 콘솔에 `localhost`만 등록했다면 `http://127.0.0.1:8080`에서는 OpenAPI 인증이 실패할 수 있으므로 로컬 개발 주소도 `http://localhost:8080`을 사용한다.

Client Secret은 브라우저용 지도 로딩에 사용하지 않으며 HTML, JavaScript, 테스트 코드, 문서 또는 Git 저장소에 절대 포함하지 않는다.

## 4. 현재 지도 및 CAD 렌더링 구조

CAD 원본은 브라우저에서 직접 해석하지 않는다. 미리 변환된 `cad-data/hopo/manifest.json`과 레이어별 JSON을 사용하며 좌표 순서는 `[longitude, latitude]`, 좌표계는 `EPSG:4326`이다.

렌더링 구조는 다음과 같다.

1. 네이버 지도를 위성지도 기본값으로 생성한다.
2. `naver.maps.OverlayView`로 CAD SVG를 네이버 지도의 `overlayLayer` pane에 장착한다.
3. 표시 중인 CAD 레이어의 도형과 문자를 SVG 요소로 생성한다.
4. 지도 투영값으로 SVG의 화면 위치와 크기를 계산한다.
5. 지도 이동 시 네이티브 오버레이 pane의 변환을 함께 사용한다.
6. 확대 애니메이션 종료 후 안정된 투영값으로 SVG를 다시 렌더링한다.

지도 생성 옵션에는 다음 설정이 적용되어 있다.

```js
overlayZoomEffect: 'all'
```

이 설정으로 확대·축소 애니메이션 중 네이버 지도의 오버레이 전체가 지도 타일과 같은 확대 효과를 사용한다. 확대 중에는 SDK가 오버레이 pane 자체를 변환하므로 애플리케이션에서 동시에 CAD 좌표를 다시 투영하지 않는다. `zoomstart`부터 `idle`까지 `zoomEffectActive` 상태로 재투영을 보류하고, `idle`에서 최신 위치와 SVG를 다시 계산한다. 이 처리가 없으면 SDK 확대와 애플리케이션 재투영이 겹쳐 도면이 화면 밖으로 이동하거나 일시적으로 보이지 않을 수 있다.

## 5. 주요 문제와 최종 해결

| 문제 | 확인된 원인 | 적용한 해결 |
|---|---|---|
| 지도 이동 시 CAD 레이어가 따라가지 않음 | CAD SVG가 네이버 지도의 네이티브 이동 계층 밖에 있었음 | `OverlayView`를 사용해 SVG를 `overlayLayer` pane에 장착 |
| 확대·축소 애니메이션 중 도면이 사라짐 | SDK 오버레이 변환과 애플리케이션의 실시간 재투영이 중복됨 | `overlayZoomEffect: 'all'` 적용, 확대 중 재투영 중지, `idle`에서 최종 재렌더링 |
| PC Edge에서 네이티브 마커도 확대 중 사라짐 | CAD 코드가 없는 최소 테스트에서도 재현되는 PC 브라우저 합성 계층 현상 | 모바일 삼성 인터넷에서는 정상임을 확인하고 PC 전용 우회는 적용하지 않음 |
| 검색 결과가 엉뚱한 위치를 기준으로 확대됨 | 이전 지도 중심에서 확대 애니메이션을 시작한 뒤 검색 위치로 이동했음 | 검색 위치를 먼저 `setCenter`한 후 목표 zoom 20으로 확대 |
| 가로모드 핀치 기준점이 실제 손가락 중심과 다름 | 화면을 회전했지만 핀치 중심점은 회전 전 좌표로 전달됨 | 두 터치의 화면 중점을 역회전해 지도 좌표로 변환하고 `zoomOrigin`에 설정 |
| 가로모드 후 세로모드에서 우측 검은 영역 발생 | 숨겨졌거나 회전된 컨테이너 크기가 네이버 지도 내부 크기에 남음 | 보이는 컨테이너 크기를 검사한 후 `map.setSize`하고 중심을 복원하는 이중 프레임 relayout 적용 |
| 메인으로 나갔다가 다시 들어오면 지도가 보이지 않음 | 숨겨진 지도 컨테이너의 크기와 이전 애니메이션 상태가 재사용됨 | 지도 종료 시 `deactivate`, 재진입 시 `initialize({ resetView: true })`와 기본 범위 재설정 |
| 브라우저 뒤로가기 시 앱 종료 | 지도 화면 자체의 History 항목이 없었음 | 지도 진입 시 `{ page: 'map' }` 상태를 추가하고 뒤로가기에서 메인 화면으로 복귀 |
| 위치 추적 중 사용자가 이동한 지도가 다시 현재 위치로 돌아옴 | 모든 위치 갱신마다 지도를 위치 마커로 이동했음 | 최초 위치 수신 때만 이동하고 이후에는 원형 현재위치와 정확도만 갱신 |
| 핀치 제스처로 전체 UI가 확대되어 버튼이 화면 밖으로 나감 | 브라우저 페이지 확대가 허용됨 | viewport에 `maximum-scale=1.0`, `user-scalable=no` 적용 |

## 6. 검색 기능 개선

도면 문자 검색은 모든 CAD 레이어의 문자 데이터를 메모리 인덱스로 구성한다. 검색 결과는 정확 일치, 앞부분 일치, 부분 일치 순으로 정렬하며 최대 100건을 표시한다.

최종 검색 UI와 동작은 다음과 같다.

- 결과 선택 시 검색 마커를 표시하고 해당 좌표를 지도 중심으로 먼저 이동
- 현재 zoom이 20보다 작으면 zoom 20까지 네이티브 애니메이션으로 확대
- 선택 결과 UI를 `검색텍스트 / 레이어 / i/n / 위·아래 화살표` 순서로 표시
- 위·아래 화살표로 이전·다음 결과 이동
- 선택된 검색텍스트를 누르면 검색 결과 목록을 다시 표시
- 검색 탐색 UI가 있으므로 기존 초록색 검색 결과 토스트는 표시하지 않음
- 가로모드에서는 검색 입력창과 결과 탐색 UI를 한 줄로 배치
- 검색 핀은 지도와 함께 회전하되 아이콘 자체는 반대 회전으로 보정해 화면에서 똑바로 표시

## 7. 위치, 문자 및 레이어 UI

현재위치 버튼은 `현재위치` 툴팁과 실시간 위치 추적 토글 기능을 제공한다.

- `watchPosition`으로 위치를 계속 갱신
- 최초 위치 수신 시에만 지도 이동 및 필요 시 zoom 18 적용
- 이후 위치 수신은 지도 중심을 강제로 변경하지 않고 마커와 정확도 원만 갱신
- 현재위치 마커는 핀 대신 파란색 원형으로 표시
- 지도 화면 종료 시 위치 추적도 정리

표시설정에서는 다음 기능을 제공한다.

- 핵심 레이어, 전체 레이어 및 전체 해제
- 레이어별 표시 선택
- CAD 투명도 조절
- 문자 표시 여부
- 문자 크기 `작게 14px`, `중간 17px`, `크게 20px`
- 설정 창 바깥 클릭 시 닫기

## 8. 화면 방향과 지도 재진입

가로모드에서는 기기 방향에 따라 지도 stage를 ±90도로 회전한다. 네이버 지도 자체는 회전 전 크기의 컨테이너를 사용하므로 화면 너비와 높이를 맞바꾸어 `setSize`한다. 도면 문자와 검색 핀은 지도 회전의 반대 각도로 보정한다.

가로모드의 드래그 이동량과 핀치 중점은 화면 좌표에서 지도 stage 좌표로 역회전해 사용한다. 핀치가 끝나면 임시 `zoomOrigin`을 해제한다.

지도 화면을 닫을 때는 진행 중인 애니메이션, 핀치 기준점, 드래그 상태와 위치 추적을 정리한다. 다음 진입에서는 다음 기본값으로 다시 연다.

- 위성지도
- 호포기지 전체 도면 범위
- 검색 결과 및 검색 마커 초기화
- 위치 추적 및 위치 표시 초기화
- 표시설정 패널 닫힘

## 9. 브라우저별 검증 결론

- PC Edge에서는 CAD 코드가 전혀 없는 네이티브 마커 테스트에서도 확대 애니메이션 중 마커가 잠시 사라졌다.
- 모바일 삼성 인터넷에서는 네이티브 마커와 SVG 모두 제스처 중 사라지지 않고 부드럽게 표시됐다.
- 따라서 PC 현상은 CAD 렌더링 오류가 아니라 PC 브라우저의 지도 합성/표시 방식 차이로 판단했다.
- 실제 사용 환경인 모바일 삼성 인터넷을 기준으로 `overlayZoomEffect: 'all'`을 운영 코드에 채택했다.

## 10. 검증 기록

최종 개발 브랜치에서는 68개 자동 테스트가 모두 통과했고, 운영 배포본의 지도 관련 변경 테스트 46개도 통과했다. 배포 완료 후 저장소를 운영 코드 중심으로 정리하면서 테스트 및 진단 코드는 제거했다. 이후 지도 변경은 운영 환경과 동일한 모바일 삼성 인터넷에서 직접 확인한다.

## 13. 유지보수 원칙

- 모바일 삼성 인터넷에서의 실제 제스처 검증을 지도 변경의 최종 기준으로 삼는다.
- 확대 애니메이션 중 CAD SVG에 별도 CSS scale이나 수동 확대 변환을 추가하지 않는다.
- 네이버 SDK가 오버레이를 변환하는 동안 CAD 좌표 재투영을 동시에 수행하지 않는다.
- 가로모드 입력은 화면 좌표를 지도 stage 좌표로 변환한 뒤 처리한다.
- 숨겨진 지도에 0 또는 1px 크기를 강제로 적용하지 않는다.
- 지도 재진입 시 이전의 검색, 위치 추적 및 애니메이션 상태를 재사용하지 않는다.
- Client Secret이나 다른 비밀값을 정적 웹 자산과 Git 저장소에 포함하지 않는다.
- 지도 로직 변경 시 JavaScript 구문 검사 후 삼성 인터넷에서 실제 제스처를 직접 확인한다.
